## Judge comments

- **Метрики (п.1):** реально есть — 296 живых сессий за 24ч, 339 M cache read, hit 95.7%, 8805 tool-вызовов, 42 записи памяти, 2302 усечения. Сомнительно — «дайджест» из `mem-metrics.sql` не является измерением этой линии вообще. Требуется — переписать скрипт на `session_v2`/`session_message` (или завести view) и **включить его в цепочку** (в `run-selftest.sh` его вызова нет вообще), иначе каждый следующий цикл будет считать по мёртвым таблицам.
- **NL-поиск (п.2):** реально есть — `plainTextMatches` дал 3/3/2 совпадения на NL-запросах, в коде `main` — `mem-record-store.ts:236`. Сомнительно — это **word-подстрочный** матч, а не семантика: запрос «ST-20261021 opencode-mem self-review» находит записи по общим словам. Требуется — ручная проверка «вопрос → правильная запись» на 5–10 NL-вопросах, и **поведение при пустом query** (сейчас возвращает всё в скоупе) — это потенциальная утечка/шум.
- **Органика памяти (п.3):** реально есть — запись/поиск работают в проде; 42 записи, тип `user_signal` освоен. Сомнительно — 100% записей сделаны авто-ревью прогонами; ни один реальный пользовательский поток память не трогал. Требуется — **хотя бы один органический сценарий** (сессия CSM/opencode, где память записана по делу и прочитана в следующей сессии) и замер, что это снижает стоимость/время.
- **Клон-ловушка (п.4):** реально есть — клон на 19 248 коммитов позади, грязный, detached; BUG-REPORT `110731` на этом основании выдал ложную тревогу про маркер усечения. Сомнительно — часть «дефектов формата» в отчётах может быть артефактом чтения не того дерева. Требуется — **прибить** локальный клон к `origin/main` (или удалить), а в трейлере selftest печатать `git rev-parse HEAD` + `git status --porcelain` **рабочего дерева** рядом с `candidate_sha`.
- **Флаги (п.5):** реально есть — `strings` по установленному бинару даёт 0 по всем четырём флагам; README `main` это подтверждает. Сомнительно — ничего: факт однозначен. Требуется — **исправить `release-current.md`** (сейчас он обещает пользователю несуществующие `OPENCODE_CACHE_MASK=0` и `OPENCODE_CACHE_MARK_IDLE_MS`) и решить судьбу v1-фич: либо порт в v2, либо явное «v1-only» в релиз-нотах.
- **Усечение (п.6):** реально есть — 2302/24ч, артефакты на диске, ретеншен работает (0 файлов старше 7 дней), cache hit 95.7%. Сомнительно — «экономия» здесь не измерена: `cache_write=0` и `cost` мертва, поэтому выигрыш в деньгах посчитать нечем. Требуется — починить `cost` (или считать по `tokens_*` с явным прайсом) и измерить hit **с** и **без** spilling.
- **Приёмка (п.7):** реально есть — 4/4 зелёные дважды подряд, `selftest-last.json` корректен, лосслесность захвата в прогоне `110731` подтверждена машинно (`cmp`/`cksum`/`sha256` совпали). Сомнительно — check'и проверяют **файлы и косвенные признаки**, а не ответ: needle не скоупится (255 сессий!), «файл полный» = одна строка, `candidate == installed` не проверяется, fallback ищет по всей БД, память пишется в прод. Требуется — скоупить needle по `session_id`, добавить check `candidate == installed` и побайтовую сверку файла, изолировать память прогонов.

## Приложение: как снимались метрики (воспроизводимо)

```bash
# Живая БД v2 — метрики сессий
sqlite3 ~/.local/share/opencode/opencode.db "
SELECT count(*) sessions, sum(tokens_input) tok_in, sum(tokens_output) tok_out,
       sum(tokens_cache_read) cache_r, sum(tokens_cache_write) cache_w,
       round(100.0*sum(tokens_cache_read)/nullif(sum(tokens_input)+sum(tokens_cache_read),0),1) hit_pct,
       round(sum(cost),2) cost
FROM session_v2 WHERE time_created > (strftime('%s','now')-86400)*1000;"

# Tool-вызовы и memory-тулы — v2-путь (session_message, а не part!)
sqlite3 ~/.local/share/opencode/opencode.db "
SELECT j.value->>'name' tool, count(*) n
FROM session_message m, json_each(m.data,'\$.content') j
WHERE m.type='assistant' AND json_extract(j.value,'\$.type')='tool'
  AND m.time_created > (strftime('%s','now')-86400)*1000
GROUP BY 1 ORDER BY n DESC;"

# Усечения
sqlite3 ~/.local/share/opencode/opencode.db "
SELECT count(*) truncated, count(DISTINCT m.session_id) sessions
FROM session_message m, json_each(m.data,'\$.content') j
WHERE m.type='assistant' AND json_extract(j.value,'\$.type')='tool'
  AND json_extract(j.value,'\$.state.metadata.truncated') IN (1,'true')
  AND m.time_created > (strftime('%s','now')-86400)*1000;"
```

Предписанный запуск (для сравнения) — `sqlite3 ~/.local/share/opencode/opencode-memory-context-v1.db < ~/.opencode/scripts/mem-metrics.sql` — даёт **пустое окно 24ч**; причина в п.1.
