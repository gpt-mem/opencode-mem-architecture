# OpenCode MEM — автономная итерация

## Миссия
Форк OpenCode, который сокращает реальную стоимость и размер LLM-контекста, сохраняя полный ретрив исходных данных. Главный критерий успеха — улучшение работающего coding-агента на реальных сессиях. Не трать шаги на второстепенное (документация, перестановка файлов, бесконечные ревью, тесты, не блокирующие основной сценарий).

Репозитории:
— архитектура: gpt-mem/opencode-mem-architecture (локально /Users/vova/opencode-mem-architecture, git remote origin, ветка main)
— код: gpt-mem/opencode-mem, клон /Users/vova/code/opencode-mem-work, целевая ветка `main` (v2, бывший `v2-base`; `memory-context-v1` — v1, мёртвая, PR туда не открывать)
— gh identity: kobzevvv. Не трогать dev/upstream/production без явного разрешения.
Проверяй актуальное состояние, а не предполагай, что ранее описанное ещё верно.

Типы сжатия (по типу контента): урлы/bash-вывод/артефакты — в SQLite с ретривом по call_id; принятые решения (решение, why, дейтайм); артефакты md/json — доступ напрямую; саммари тулов; эмбеддинги; PII — отдельно. Философия: сжимаем, но ничего не прячем — LLM может всё достать.

## Инварианты (нарушать нельзя)
— OpenCode хранит полную историю в SQLite. MEM сжимает ТОЛЬКО модельное представление истории. Оригиналы не удалять и не повреждать ради экономии.
— В каждом компакт-маркер — рабочий путь восстановления (call_id → get_tool_call_details). Если путь недоступен — не утверждать, что данные восстановимы.
— System Context Epoch, permissions, инструкции пользователя, протокольное состояние — не изменять.
— PII/credentials: секреты не попадают в previews, markers, embeddings, логи и диагностику. Для credentials — только metadata и безопасные ссылки; originals — через авторизованные механизмы OpenCode.
