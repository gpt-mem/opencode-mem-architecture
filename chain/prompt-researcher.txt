## Задача
1. **Метрики**: запустить SQL из mem-metrics.sql; включить дайджест (token costs, cache hit %, memory tools usage, intent signals) в отчёт.
2. **Обновить STUDY.md** — переранжировать список по полезности на основе новых данных:
   - что **доказано** (работает стабильно, метрики подтверждают)
   - что **сомнительно** (нужно больше доказательств,ベンчмарк нестабилен)

4. **User feedback**: паттерны из CSM sessions.db — частые ошибки, жалобы, feature requests. Ранжировать по частоте.

## Формат вывода
Перезаписать `~/opencode-mem-architecture/STUDY.md` (полная актуальная версия) с секцией:
```
# STUDY <STAMP>

## Ranked by usefulness
1. <пункт> — <usefulness: high|medium|low> — STATUS: <proven|doubtful|needs_proof> — <1 строка обоснование>
...

## Metrics digest (24h)
- Sessions: N, Total tokens: X, Cache read: Y (Z%), Cost: $C
- Memory tools: overview=A, find=B, detail=C calls
- Intent signals: cosine_avg=X, acted=Y%

## User feedback top
1. <паттерн> — count=N — severity=...
...

## Judge comments
- <пункт>: <кратко что реально есть, что сомнительно, что требуется>
```

## Правила
- Не отправлять тяжёлые данные в Cloudflare — только мелкие дайджесты (debug-logs worker уже работает, не добавлять bulk).
- Ценные примеры/находки → коммитить в docs репо (git add STUDY.md && commit -m "research: <STAMP>" && push).
- Не перезапускать себя.
- Консервативно: не завышать STATUS без доказательств.
