# Дозор за апстримом (GHA + opencode)

Регулярный workflow `.github/workflows/upstream-watch.yml` в этом репозитории: внутри
крутится **наш opencode** (форк `gpt-mem/opencode-mem`, линия `v2-base`), он изучает новый
релиз апстрима и собирает годное в форк.

## Схема

```
schedule (каждые 6 ч) / workflow_dispatch
        │
        ├─ collect  ── дешёвый детектор (python, без модели)
        │             «есть ли новый тег апстрима?»
        │             новых нет → дальше не идём, токены не тратятся
        │
        ├─ study    ── opencode-сессия «изучить»
        │             читает сырьё + профиль продукта →
        │             разбор по классам PORT / ASK / SKIP →
        │             отчёт + issue в gpt-mem/opencode-mem
        │
        └─ port     ── opencode-сессия «собрать» (отдельный этап)
                      переносит PORT на v2-base, проверяет профиль,
                      открывает черновик PR (merge — за человеком)
```

## Файлы

| Файл | Что это |
|---|---|
| `.github/workflows/upstream-watch.yml` | сам workflow: расписание, сборка форка под linux-x64, запуск сессий |
| `chain/upstream_collect.py` | детектор: теги, диапазон, коммиты, PR, файлы — только факты |
| `chain/run-upstream-collect.sh` | локальный запуск детектора (без модели, секунды) |
| `chain/prompt-upstream-study.txt` | промпт сессии «изучить» |
| `chain/prompt-upstream-port.txt` | промпт сессии «собрать» |
| `chain/upstream-policy.json` | профиль продукта: что держим, что мимо, обязательные файлы |

## Профиль продукта (`chain/upstream-policy.json`)

Правится вручную — это единственный файл, который описывает, что для нас «годно»:

- **держим**: терминальный агент (`packages/tui`, `packages/cli`, `packages/core`) без
  нативного приложения и без веба; экономию токенов (усечение вывода инструментов +
  компактификация сессии); наши фишки (детектор doom-loop, свой spawner, миграция БД без
  леджера масок);
- **мимо**: `packages/app`, `packages/desktop`, `packages/web`, `packages/session-ui`,
  `packages/gui-extensions`, сайты/статистика/публикации;
- **обязательные файлы** (`must_keep`) и **запрещённые** (`must_not_return`) — проверяются
  перед открытием PR.

## Классы изменений

| Класс | Что значит | Что с ним делает автоматика |
|---|---|---|
| PORT | берём в порт | переносится на `v2-base` автоматически |
| ASK | задевает наши правки (файлы расхождения, схема БД, миграции) | ждёт решения человека; в PR попадает только если человек написал «тянуть» в issue |
| SKIP | вне нашего продукта | не переносится |

Расхождение считается по merge-base с апстримным HEAD: только наши коммиты и только
наши файлы (compare-по-файлам обрезается на 300 файлах и тащит общие изменения).

## Запуск вручную

```bash
# детектор (секунды, без модели) — что вообще есть нового
bash chain/run-upstream-collect.sh

# разбор конкретного тега с нуля
UPSTREAM_BASE_TAG=v2.0.30 bash chain/run-upstream-collect.sh

# сессия «изучить» локально (нужен установленный opencode и ключ ladder)
UPSTREAM_TAG=v2.0.33 \
UPSTREAM_COLLECTED=~/.opencode/scripts/upstream-watch/collected/v2.0.33.json \
UPSTREAM_POLICY=$PWD/chain/upstream-policy.json \
UPSTREAM_OUT_DIR=/tmp/upstream-out \
opencode run --standalone --model ladder/build --auto "$(cat chain/prompt-upstream-study.txt)"
```

## Секреты репозитория

| Секрет | Зачем |
|---|---|
| `GH_PAT` | classic PAT: чтение форка и апстрима, запись issue/PR, push веток |
| `LLM_LADDER_TOKEN` | ключ провайдера ladder для opencode-сессий |

## Чего workflow не делает

- Не мержит PR — merge за человеком.
- Не публикует релиз форка и не подменяет установленную сборку.
- Не трогает `v2-base` и чужие ветки.
- Не закрывает issue сам: closing-ключевые слова на этой линии не применяются.

## Известные ограничения

- Апстрим не публикует GitHub-релизов в линии `v2.*` — только теги. Дозор ловит **теги**.
  Накопленные после релиза коммиты видны в логе как «апстрим накопил N коммитов» и попадут
  в разбор следующего тега.
- Сборка форка внутри workflow идёт на `ubuntu-latest` (linux-x64) и кэшируется по SHA
  `v2-base`; первый прогон — минуты, дальше — секунды.
- Если ключ ladder недоступен или провайдер деградировал — сессия упадёт, workflow покажет
  это красным, ничего не будет записано в форк.
